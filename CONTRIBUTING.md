# Contributing

## Setup

Python >= 3.11 and [uv](https://docs.astral.sh/uv/). Clone, then:

```sh
uv sync --group dev
```

## The gate

Every change must pass, before every commit:

```sh
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Changes that touch `docs/`, `mkdocs.yml`, or public docstrings also build the
site and verify the generated schema pages:

```sh
uv run --group site zensical build --strict
uv run fabric-etl docs --registry fabric_etl.load.control --out docs/schema --check
```

A `--check` failure means the committed `docs/schema/` output is stale —
regenerate it with the same command without `--check` and commit the result.

## Commits

- Topic branch off `main`; history lands via `--no-ff` merges.
- Conventional commits: `feat(entities): ...`, `fix(extract): ...`,
  `docs(site): ...`, `chore(build): ...`, `ci(pages): ...` — match
  `git log --oneline` for precedent.
- Every commit is signed off (`git commit -s`) and SSH-signed; unsigned
  commits are not merged.
- Each feature commit carries its tests. No production code without a
  covering test.

## Layout rules

- Dependency rule: `entities`, `transform`, `docs`, `static` never import
  `extract` or `load`. Everything under those four must import with only
  pydantic installed.
- Heavy dependencies (pyodbc, lxml, httpx, pyspark, azure) are extras,
  imported lazily with an `ImportError` naming the extra.
- Version pins (zensical included) change only deliberately, never as a
  side effect of another change.

## Docs

Guide and API pages live in `docs/`; the API reference renders from
docstrings via mkdocstrings (Google style — keep `Args:`/`Raises:` sections
accurate when touching public signatures). Preview locally:

```sh
uv run --group site zensical serve
```

`docs/schema/` is generated by `fabric-etl docs` from the package's own
control entities — edit the entities, not the pages.

## Releases

Version bump + `CHANGELOG.md` entry on a `release/x.y.z` branch, merged to
`main`, then an annotated signed tag `vx.y.z` — pushing the tag triggers the
PyPI publish workflow.
